# 使用指南

[返回首页](../README.md)

## 最近项目

按 `Ctrl+Alt+Space` 唤出项目面板。每次打开都会刷新历史、清空搜索并聚焦输入框；空搜索按最近访问顺序显示，输入后按项目名和路径模糊匹配。

| 操作 | 快捷键或鼠标动作 |
| --- | --- |
| 选择项目 | `↑` / `↓`，或单击；到首尾时停止 |
| 按页移动 | `Page Up` / `Page Down` |
| 打开项目 | `Enter` 或双击 |
| 展开或收起完整路径 | `Alt+Enter` 或底部信息按钮；展开后可选中并复制路径 |
| 聚焦并全选搜索 | `Ctrl+K` / `Ctrl+F` |
| 刷新历史 | `Ctrl+R` |
| 打开管理窗口 | `Ctrl+,` 或右上角设置按钮 |
| 收起面板 | `Esc` 或切换到其他窗口 |

面板内的 `Ctrl` 组合键在 macOS 上也支持对应的 `⌘` 组合键。列表会缩短较长路径的中间部分，保留开头和末尾；悬停或展开详情可查看完整路径，远程项目另有标记。详情展开时，第一次 `Esc` 收起详情，再次按下才收起面板。打开成功后面板收起；失败时保留搜索结果并显示错误。

项目列表来自 VS Code Stable 标准用户目录的历史记录，包括本地文件夹、`.code-workspace` 文件和远程 URI。数据库以只读方式打开，普通最近文件不列入项目列表。可在设置中指定 VS Code 可执行文件；Insiders、便携版、自定义数据目录和自定义 profile 暂不支持自动发现。

## 应用快捷键

在管理窗口的“窗口切换”页搜索或选择已有应用，也可以添加新应用。基本编辑区集中显示程序、显示名称、快捷键和窗口行为；选择程序后，新配置会建议名称和匹配规则，仍可修改。

点击快捷键旁的“录制”，等待“准备录制”结束、显示录制提示后，再按所需组合键，也可以直接输入快捷键文字。`Esc` 取消录制并保留原值，`Backspace` 或 `Delete` 清空当前快捷键。录制期间，本工具已注册的快捷键会交给录制框，退出录制后恢复原有功能。语法错误或与其他配置重复时，在字段旁提示；其他软件占用等系统注册问题在保存时报告，草稿会保留。

匹配标识、配置 ID、目标系统、启动参数和其他启动候选在“高级选项”中。匹配标识因平台而异：

| 平台 | 匹配标识示例 |
| --- | --- |
| Windows | 进程文件名，如 `Code.exe`；也支持 `class:<窗口类名>` 精确匹配窗口类 |
| macOS | bundle ID、应用名或可执行文件名，如 `com.microsoft.VSCode` |
| Linux X11 | WM_CLASS 或进程文件名，如 `org.wezfurlong.wezterm` |

普通切换模式的行为：

- **没有窗口**：按顺序尝试启动候选。一个候选启动成功后等待窗口出现。
- **一个窗口**：窗口在前台时最小化，否则切回该窗口。
- **多个窗口**：按稳定顺序依次切换。开启连续循环时，末尾回到第一个窗口；关闭时，末尾将全部窗口最小化，再次按键从头开始。

切换到其他应用后，再按快捷键会接着上次的位置选择下一个窗口。“仅最大化新窗口”用于启动时的窗口大小；已有窗口保留原尺寸。应用启动期间主动切换到其他窗口，会停止自动聚焦。

默认配置包含 WezTerm `F3`、VS Code `F4` 和 Chrome `F5`。Windows 会尝试常用安装目录，macOS 使用 `/Applications`，Linux 使用 `PATH`；安装位置不同时，在编辑区修改启动程序。

“保存应用”成功后留在当前编辑区，继续调整无需重新选中。“测试已保存配置”使用最近一次成功保存的内容，编辑中的草稿仍会保留。只有当前系统支持、已启用且已有保存版本的应用才能测试；通用设置中关闭应用快捷键时也不可测试。列表搜索不会改变配置身份，删除与切换应用时的放弃修改确认会明确说明具体操作。

### WezTerm 下拉终端（Windows）

Windows 新配置默认使用 `F3` 唤出独立的 WezTerm 下拉窗口，显示在鼠标所在显示器的顶部，占工作区全部宽度和一半高度。终端在前台时再按 `F3` 隐藏，再次唤出时继续同一个 shell；隐藏期间，命令和终端任务继续运行。

已有配置在应用编辑区选择 WezTerm，勾选“启用 WezTerm 独立下拉”，保存即可。快捷键、启动参数和工作目录沿用已保存的内容；安装位置不同时，选择本机的 `wezterm-gui.exe`。

下拉终端与普通 WezTerm 窗口分开管理，窗口身份由工具箱自动设置。字体、配色、默认 shell（`default_prog`）继续读取你的 WezTerm 配置。下拉窗口去掉标题栏、保留可调整大小的边框；改变字号时保持外框尺寸。

收起使用 Windows 窗口隐藏。退出工具箱，或停用、移除该应用配置后，工具箱会把它隐藏的窗口恢复为可见，终端会话继续保留。只关闭工具箱的管理界面时，快捷键仍可使用。

### Quake 停靠

在应用编辑区的“下拉与停靠”中开启停靠，将一个应用窗口放在屏幕边缘。同一快捷键始终唤回这个窗口；窗口在前台时再按一次收起。Windows 使用隐藏，macOS 和 Linux X11 使用最小化。

- 停靠方向：上、下、左、右。
- 尺寸：显示器可用工作区的 10–100%，宽高分别设置。
- 对齐：起始、居中、末端。
- 显示器：鼠标所在显示器、前台窗口所在显示器、主显示器。
- 预设：顶部半屏、右侧边栏、铺满工作区。编辑区可预览布局，保存后下次唤起应用。

定位使用显示器工作区，避开任务栏或 Dock；最终尺寸还受目标应用最小尺寸和终端字符网格影响。

| 选项 | 支持平台 |
| --- | --- |
| 显示时置顶 | Windows、Linux X11；收起或退出工具箱后恢复原置顶状态 |
| 失去焦点时自动收起 | Windows；所属对话框获得焦点时保持显示 |

macOS 的窗口定位需要辅助功能权限；Linux 需要 X11、EWMH 窗口管理器和 XRandR 1.5。Quake 模式使用自己的窗口和尺寸设置，普通模式的连续循环、启动最大化选项在关闭 Quake 后使用。

## Skills 管理

从托盘或管理窗口打开“Skills 管理”，也可以运行 `sean-toolbox show skills`。此功能参考 CC Switch 的集中管理方式，主副本保存在工具箱配置目录下的 `skills/`，再按所选应用部署。默认使用符号链接；可在“仓库”页的“默认部署方式”中切换为复制，列表底部的“部署设置”也可进入此处。

### 添加、发现与安装

1. 在“仓库”页的来源区域填写 `owner/repo` 或 `https://github.com/owner/repo`，例如 `sean2077/skills`。分支留空时跟随仓库默认分支，也可填写指定分支。添加成功后自动进入“发现”并读取来源。首次使用会预置官方 `anthropics/skills` 来源，也可以移除后添加其他来源。
2. 在“发现”中搜索名称、描述或来源，点击条目进入详情，选择需要启用的应用，然后安装。只读取 `SKILL.md` 开头的元数据，正文较长不影响发现；格式无法识别的条目会被跳过，并显示提示，不影响其他技能。重新发现会按当前仓库重新生成跳过提示，移除仓库时也会清除其提示。
3. 在“已安装”中通过每行的应用按钮调整部署状态；窄窗口可进入详情调整。也可按状态和来源筛选，勾选多个技能后，点击批量栏中的应用图标为所选技能统一启用或停用：图标带勾表示所选技能都已部署，点击会全部停用；带“−”表示部分部署，与未部署时一样，点击会全部启用。悬停图标可查看部署数量和点击效果。切换筛选保留选择，批量栏会同时显示已选数量和当前筛选隐藏的数量；“清除选择”清除全部选择。来源筛选按仓库记忆，移除该仓库后回到“全部”。在详情中操作使技能离开当前筛选时，详情仍停留在该技能上。
4. 点击技能查看详情，包括完整描述、源路径、主副本或链接方式、版本、各应用部署目录和具体错误。每行右侧的“···”提供单独更新（仅仓库来源）或卸载（需确认）。“操作状态”集中查看更新计划、操作状态和真实条目错误。
5. 已安装列表中，技能名称右侧依次显示来源标签和启用状态（“已启用”高亮，“未启用”为灰色）。来源标签显示为 `owner/repo@提交`，例如 `sean2077/skills@1447723`，用于和上游最新提交对比；点击标签（或在详情中点击“打开来源”）在浏览器中打开该提交下的技能目录，链接技能打开其源目录，本机复制的技能打开主副本目录。

仓库下载需要 Git 可执行文件位于 `PATH`。程序不弹出交互式登录；私有仓库需要提前配置可用的 Git 凭据。网络错误或没有访问权限会显示在仓库和操作结果中，保留已安装版本。

| 应用 | 默认部署目录 |
| --- | --- |
| Claude Code | `~/.claude/skills` |
| Codex | `~/.codex/skills` |
| Gemini CLI | `~/.gemini/skills` |
| OpenCode | `~/.config/opencode/skills` |
| Grok Build | `~/.grok/skills` |

这里的 `~` 为当前用户主目录，目前使用这些默认路径，不读取 CC Switch 的自定义路径设置。Codex 使用自定义 `CODEX_HOME` 时，需要自行将目标保持在实际读取的位置；本版没有应用路径覆盖设置。

开关控制工具箱在对应目录中的部署。共享的 `~/.agents/skills` 不作为主副本目录。OpenCode、Grok Build 还可能读取 `~/.claude/skills`，各工具也可能读取项目目录或其他兼容目录，因此关闭某个部署开关不保证应用从所有来源停用该 Skill；必要时同时整理兼容目录，或使用对应应用的原生禁用设置。

### 部署方式

“仓库”页的“默认部署方式”对仓库安装和“复制”导入的受管技能生效，默认“符号链接”，也可以切换为“复制”。安装和复制导入详情中也可调整同一全局设置，选择后立即保存。切换只改变之后启用的应用目录；已有部署保持原方式，关闭再打开该技能对应的应用开关，即可按当前方式重新部署。链接方式的本机导入始终使用符号链接，不受此设置影响。

- **符号链接**：应用目录是指向主副本的符号链接。更新主副本后，所有已启用目录立即读取新内容，不额外占用空间。Windows 需要开发者模式或符号链接权限；创建失败时操作会报错，可切换为复制后重试。
- **复制**：每个应用目录保存独立副本，不需要额外系统权限。更新、停用和卸载会校验副本指纹，检测到本地修改时停止操作。

也可以运行 `sean-toolbox skills deploy symlink` 或 `sean-toolbox skills deploy copy` 切换。部署方式与每日更新保存在 `skills/state.json`，不写入配置文件 `config.json`。

### 本机导入与移除

可以扫描上述应用目录，以及共享的 `~/.agents/skills`、CC Switch 的默认主副本目录 `~/.cc-switch/skills`，或者选择一个包含 `SKILL.md` 的本机文件夹。两种入口都会先显示导入确认，核对源目录，再选择添加方式和目标应用：

- **复制**（默认）：保存独立主副本，再按当前部署方式链接或复制到所选应用目录；链接方式在 Windows 需要开发者模式或符号链接权限。
- **链接**：保留原目录，并在所选应用目录创建指向它的符号链接；源目录的修改立即生效，不参与远程更新。Windows 需要开发者模式或符号链接权限。

应用目录中的符号链接或 Windows junction 会在“本机技能”中列为链接条目并显示目标。选择“链接”导入可接管已经指向同一来源的链接；选择“复制”则读取真实目标并复制。指向其他位置的已有目录不会被覆盖。扫描到或选择的文件夹与已管理技能同名（不区分大小写）时，确认页改为提供“查看已安装技能”，不会重复导入。

启用前会检查目标目录：受管技能不会覆盖已存在且不由工具箱管理的同名目录或链接，即使内容相同；链接方式的本机导入只接管指向同一来源的链接。导入原应用目录后，如果希望由工具箱管理该位置，请先将原目录移出，再启用对应部署。停用和卸载只操作工具箱登记的副本或链接，链接的源目录始终保留；检测到主副本、部署目录或应用链接有本地修改或替换时，操作会停止并显示冲突。请先自行保留、整理冲突目录，再重试；不会静默丢弃修改。

### 每日自动更新

“每日自动更新”默认关闭，可在 Skills 页面直接开启。开启后立即检查，之后每次全量更新成功间隔 **24 小时**再更新；部分失败后 **1 小时**重试。仅更新已经安装且有仓库来源的 Skills，不自动安装新发现的 Skills，也不更新无来源的本机导入项。

调度由宿主管理：关闭管理界面后继续执行；退出整个工具箱或关机期间不运行，下一次启动时补跑已到期任务。希望登录后自动开始，可在通用设置中同时开启“开机启动”。界面显示上次尝试、上次成功、下次更新和错误；手动更新与自动更新串行执行。

更新前检查主副本及各启用目录的内容指纹，遇到本地修改会跳过该项并保留原文件；其他无冲突项仍可继续更新。符号链接部署直接跟随主副本更新；复制部署会替换各应用副本。每项先准备完整目录，再替换文件与状态，失败时回滚。仓库下载不会执行 Skill 内的脚本。

Skills 的独立状态（包括部署方式和每日更新）与主副本保存在配置目录的 `skills/`，不包含在“设置”页的应用配置 JSON 导出中。链接技能只在状态中记录源目录，源目录本身不在工具箱数据目录内，备份时需单独保留。备份时先退出工具箱，再保留该目录、相关应用目录和链接技能的源目录。本次支持仓库和本机目录管理；未提供 CC Switch 的 skills.sh 市场搜索、ZIP 导入及备份恢复界面。

## 设置与界面关闭

设置中可切换中文或英文、选择跟随系统或固定明暗主题，分别启停最近项目和应用快捷键，并设置开机启动。语言和主题都会即时预览，保存后保留，撤销时恢复。语言预览同步更新管理窗口、最近项目面板及其操作提示和摘要；托盘菜单在保存语言设置后更新。

应用与通用设置分别保留草稿，导航会标记尚未保存的修改。窗口较窄时，导航自动折叠为带提示的图标，主内容继续可滚动使用。设置页按功能分为“通用”“最近项目”“窗口切换”“技能管理”“配置文件”五类，左侧切换；搜索时跨类显示匹配项。保存失败时自动切到出错字段所在的分类。保存与撤销操作固定在底部，对所有分类生效。Skills 操作直接提交到宿主，不依赖通用设置的保存按钮。

| 管理窗口操作 | 快捷键 |
| --- | --- |
| 搜索当前页面 | `Ctrl+F`；在状态页聚焦诊断详情 |
| 返回并搜索最近项目 | `Ctrl+K` |
| 新增应用（应用页） | `Ctrl+N` |
| 保存当前编辑页 | `Ctrl+S` |
| 最近项目 / 窗口切换 | `Ctrl+1` / `Ctrl+2` |
| 设置 / 运行状态 / Skills | `Ctrl+3` / `Ctrl+4` / `Ctrl+5` |

macOS 也支持上述快捷键对应的 `⌘` 组合键；悬停导航项可查看对应快捷键。确认框和 Skills 详情优先接收 `Esc`，先退出当前确认或详情，再处理窗口关闭。

“自动收起后缓存”控制最近项目面板在失焦或打开项目后收起时，界面进程保留多久。默认 `0` 秒，可设为 `1–3600` 秒以加快再次唤起。已有配置沿用保存的数值。

主动点击关闭按钮、选择“关闭界面”或按 `Esc` 关闭最后一个界面时，进程立即退出。另一界面仍可见、存在草稿、文件对话框或操作尚未完成时，会继续保留界面进程。关闭有修改的管理窗口时，会询问是否放弃修改。托盘和全局快捷键由常驻宿主继续处理。

## 配置文件

日常设置可直接在界面修改。配置文件位置如下，也可运行 `sean-toolbox config-path` 查看。

| 系统 | 路径 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\SeanToolbox\config.json` |
| macOS | `~/Library/Application Support/SeanToolbox/config.json` |
| Linux | `$XDG_CONFIG_HOME/sean-toolbox/config.json`；变量未设置或不是绝对路径时，使用 `~/.config/sean-toolbox/config.json` |

手动修改前先退出工具箱，修改后重新启动。解析失败时会保留文件并报告错误。配置文件上限 1 MiB，最多 100 个应用，每个应用包含 1–8 个启动候选。

### 分组结构

配置按所属模块分组。版本 `2` 使用下面的结构；版本 `1` 的扁平配置在读取后自动迁移，并在下次保存时写为分组格式。

```json
{
  "schema_version": 2,
  "general": {
    "language": "zh-CN",
    "theme": "system",
    "autostart": false
  },
  "projects": {
    "enabled": true,
    "hotkey": "Ctrl+Alt+Space",
    "vscode_path": null
  },
  "windows": {
    "enabled": true,
    "profiles": []
  },
  "ui": {
    "idle_seconds": 0
  }
}
```

| 分组 | 字段 | 含义与默认值 |
| --- | --- | --- |
| `general` | `language` | `"zh-CN"` 或 `"en"`，默认 `"zh-CN"` |
| `general` | `theme` | `"system"`、`"light"` 或 `"dark"`，默认 `"system"` |
| `general` | `autostart` | 开机启动，默认 `false` |
| `projects` | `enabled` | 最近项目开关，默认 `true` |
| `projects` | `hotkey` | 项目面板快捷键，默认 `"Ctrl+Alt+Space"` |
| `projects` | `vscode_path` | VS Code 可执行文件路径，默认 `null`，由程序查找 |
| `windows` | `enabled` | 应用快捷键开关，默认 `true` |
| `windows` | `profiles` | 应用配置数组，最多 100 项 |
| `ui` | `idle_seconds` | 自动收起后的界面缓存秒数，默认 `0`，范围 `0–3600` |

未知字段会被拒绝；手写配置时请保留 `schema_version`。Skills 的部署方式、每日更新和已安装列表保存在独立的 `skills/state.json`，不在这个文件中。

### 应用配置示例

下面是一项 Windows 应用配置，放在 `windows.profiles` 数组中：

```json
{
  "id": "vscode",
  "name": "VS Code",
  "platform": "windows",
  "matcher": "Code.exe",
  "hotkey": "F4",
  "enabled": true,
  "maximize": false,
  "cycle_continuous": true,
  "launch": [
    {
      "executable": "%LOCALAPPDATA%\\Programs\\Microsoft VS Code\\Code.exe",
      "args": ["--new-window"],
      "cwd": null
    }
  ]
}
```

`platform` 可取 `windows`、`macos`、`linux`，应用配置只在对应平台启用。`id` 用于命令行切换和导入合并；`cycle_continuous` 控制多个窗口切换到末尾后是否回到第一个。

启动参数使用 JSON 字符串数组，例如 `["--new-window", "D:\\Work\\My Project"]`。程序路径和工作目录支持 `~`、`%VAR%`、`${VAR}` 展开；参数按原样逐项传递。Windows 应用启动项填写 `.exe` 路径。最近项目模块还支持从标准安装布局中的 `code.cmd` 定位到 `Code.exe`。

### Quake 字段

在应用配置中加入 `quake` 对象；省略该字段时使用普通切换模式：

```json
{
  "enabled": true,
  "edge": "top",
  "alignment": "center",
  "width_percent": 100,
  "height_percent": 50,
  "monitor": "cursor",
  "always_on_top": false,
  "hide_on_focus_loss": false
}
```

`edge` 支持 `top` / `bottom` / `left` / `right`；`alignment` 支持 `start` / `center` / `end`；`monitor` 支持 `cursor` / `foreground` / `primary`。置顶和失焦收起的适用平台见前面的 Quake 选项表。

### 导入与导出

设置页可导出当前已保存的 JSON 配置，也可导入工具箱 JSON 或 WinGuake 格式的 INI。选择文件后先预览，检查应用列表、快捷键和提示，再应用。

- **合并**：按 `id` 更新同名应用并追加新应用，`id` 比较不区分大小写；通用设置保持当前值。
- **替换 JSON**：采用文件中的应用列表和通用设置。
- **替换 INI**：采用导入的应用列表，通用设置保持当前值。INI 导入项属于 Windows 配置。

无法转换的快捷键会留空并提示手动设置。保存时校验配置和快捷键冲突，通过后写入文件并应用。

## 命令行

```text
sean-toolbox                              打开最近项目面板
sean-toolbox show projects                打开最近项目面板
sean-toolbox show windows                 打开应用快捷键配置
sean-toolbox show settings                打开设置
sean-toolbox show diagnostics             打开运行状态
sean-toolbox show skills                  打开 Skills 管理
sean-toolbox --background                 启动常驻宿主
sean-toolbox toggle vscode                切换 id 为 vscode 的应用
sean-toolbox status                       输出 JSON 运行状态
sean-toolbox config                       输出当前配置与修订版本
sean-toolbox config-path                  输出配置文件路径
sean-toolbox skills list                  输出 Skills 状态、仓库及清单
sean-toolbox skills discover              提交仓库发现任务
sean-toolbox skills update                提交全部仓库来源 Skills 更新
sean-toolbox skills daily on              开启每日自动更新
sean-toolbox skills daily off             关闭每日自动更新
sean-toolbox skills deploy symlink        新启用的应用目录使用符号链接
sean-toolbox skills deploy copy           新启用的应用目录使用复制
sean-toolbox quit                         退出宿主和界面
sean-toolbox --version                    显示版本
sean-toolbox --help                       显示帮助
```

打开界面的命令会按需启动宿主。`status`、`config`、`toggle`、`skills`、`quit` 需要宿主正在运行；`config-path`、`--version` 和 `--help` 可直接使用。后台启动日志位于配置目录的 `host.log`。

Skills 命令立即返回是否接受任务，接受不代表更新完成。使用 `sean-toolbox skills status`（等同 `list`）查看 `skills.busy`、`skills.last_error` 和各项结果；更新完成后 `busy` 变为 `false`。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 快捷键没有响应 | 在“运行状态”检查注册结果，调整与系统或其他应用冲突的快捷键 |
| 应用可以启动但无法切回窗口 | 核对匹配标识；Windows 检查目标应用的权限，macOS 检查辅助功能授权 |
| macOS 更换安装位置后无法控制窗口 | 在“系统设置 → 隐私与安全性 → 辅助功能”重新授权，再到运行状态页重新检查 |
| Linux 没有托盘图标 | 确认桌面提供托盘宿主；也可通过命令行打开界面 |
| Linux 无法选择导入或导出文件 | 安装并启用 XDG Desktop Portal 文件选择后端，或安装 `zenity` |
| 最近项目列表为空 | 先在 VS Code Stable 中打开项目，再刷新；确认使用的是标准用户数据目录 |
| 关闭面板后仍有界面进程 | 检查缓存时间、另一个可见窗口、未保存草稿及尚未完成的操作 |
